# L3 第1课 · 让 OTTO 在电脑里活过来 · 90分钟课堂 SOP

> 版本：v1.0 | 适用年级：12-14岁 | 班级：20人（2人/组，共10台电脑）| 课时：90分钟
> 课程目标：学生能用 MuJoCo 仿真跑通 OTTO 步态寻优，并亲眼看到强化学习"学会站稳但没学会走路"的真实结果
> 配套资产：[`growth/labs/L3-mujoco-rl/`](/growth/labs/L3-mujoco-rl/) · [实验室 README](/growth/labs/L3-mujoco-rl/README.md)

## 〇、教师必读：本课的全部实测数据

本课所有数字均为**在无 GPU 机器上实测所得**（2026-10-30，16 核 CPU），不是估算。课上可直接引用。

| 指标 | 实测值 |
|---|---|
| MuJoCo 安装耗时 | 12 秒 |
| 无头物理仿真速度 | 226,286 步/秒（452× 实时） |
| gymnasium 随机步速度 | 20,362 步/秒（10 万步 ≈ 1 分钟） |
| OTTO 环境随机步速度 | 29,677 步/秒 |
| Tier A 网格搜索 | 240 组参数 / 0.5 秒 |
| PPO 训练速度 | 3,528 步/秒（40 万步 = 1.9 分钟） |
| 随机策略基线回报 | **-9.479**（20 回合平均，几乎立刻摔倒） |
| PPO 40 万步后回报 | 最高爬到 **216**，评估平均 47.57 |
| PPO 40 万步后位移 | 平均 **1.5cm**，正向回合均值 8.6cm，最远 9.9cm |
| PPO 300 万步对照 | 15.2 分钟；回报 86.4，位移 **1.0cm（不升反降）**，最远单回合 43.6cm，曲线剧烈震荡 |
| Tier A 最优手写步态 | 位移 **+31.8cm**，但站立仅 0.7 秒（是"扑倒着挪"，不是走） |
| 离屏渲染 | **本机全黑**（EGL / OSMesa / Xvfb 三种后端均不通）→ 本课不看视频，看数据 |

> **给教师的一句话**：这节课最有价值的不是"教会 MuJoCo"，而是让学生亲眼看到 **"学会不摔倒"和"学会往前走"是两个难度台阶**。这个认知比任何 API 都值钱。

## 一、课前准备清单

### 1.1 环境准备（课前 1 周，教师完成）

**这一步决定课程成败 —— 不要让学生现场装环境。**

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 1 | 教师机上执行 `pip install -r requirements.txt` | 无报错 |
| 2 | 把 `growth/labs/L3-mujoco-rl/` 打包分发给 10 台学生机 | 10 台全部就位 |
| 3 | 学生机统一执行 `pip install -r requirements.txt`（**课前一周**完成） | 全部成功 |
| 4 | 课前 2 天在 10 台机器上各跑一次 `python 01_gait_search.py` | 10 台均输出 Top 5 |
| 5 | 教师机预训练一个 PPO 模型备用（`02_train_ppo.py 400000`） | 生成 `otto_ppo.zip` |

**⚠️ 三个必踩的坑（教师提前知道，别在课上现查）**

1. **不要装 CUDA 版 torch**。stable-baselines3 会自动拉 CPU 版（约 200MB），学生机装 CUDA 版会下载 2GB+ 直接卡死网络。
2. **离屏渲染会全黑，这是正常现象不是环境坏了**。本课设计就是用 matplotlib 数据图代替视频（`03_analyze.py`）。如果课上有学生问"为什么是黑的"，这正好是引入"数据思维"的好时机。
3. **`otto_model.xml` 用相对路径**。脚本假定在 `L3-mujoco-rl/` 目录下运行，讲课前先 cd 到该目录。

## 二、90分钟时间轴

### 2.1 开场 + 制造问题（0:00 - 0:12 | 12分钟）

```
┌─────────────────────────────────────────────────────┐
│ 环节：让 OTTO 走两步，然后告诉学生"这是假的"                    │
└─────────────────────────────────────────────────────┘
```

| 时间 | 时长 | 教师动作 | 学生动作 | 话术要点 |
|---|---|---|---|---|
| 0:00 | 3min | 展示实物 OTTO，让它走两步 | 围观 | "这是你们在 L1 组装的 OTTO，它会走路。" |
| 0:03 | 4min | 屏幕切到终端，跑 `03_analyze.py`，展示位移曲线 | 看曲线 | "现在我们把它放进电脑里。注意——**它不是录像，是正在算的**。" |
| 0:07 | 5min | 打开 `otto_model.xml`，指着 body/joint/actuator | 观察 | "这具身体有 4 条腿关节、2 条手臂关节，**跟你们手上那台一模一样**。" |

**核心话术（务必讲到）**：
> "你们 L2 学的是'给它下指令，让它做动作'。今天不一样 —— 我不给它任何指令，我**只告诉它什么叫'走得好'**，剩下的它自己试。"

**预期效果**：学生意识到"指令"和"目标"是两件事。

---

### 2.2 Tier A：手写步态 + 网格搜索（0:12 - 0:42 | 30分钟）

```
┌─────────────────────────────────────────────────────┐
│ 环节：先让"电脑帮我们找最优动作" —— 建立"优化"直觉               │
└─────────────────────────────────────────────────────┘
```

**教师演示（8分钟）**

1. 运行 `python 01_gait_search.py`
2. 现场展示：240 组参数、**0.5 秒**跑完
3. 指着输出解释四个参数：A 髋摆幅 / B 膝弯曲 / freq 步频 / phase 左右相位差

**话术**：
> "我们不知道最优步态长什么样，所以穷举 240 种组合，每种都让机器人真跑 6 秒，谁走得远谁赢。**这叫网格搜索 —— 笨办法，但有效**。"

**学生动手（18分钟）**

任务卡 L3-01：

| 任务 | 操作 | 目标 |
|---|---|---|
| 任务 1 | 跑 `01_gait_search.py`，记录 Top5 中位移最大的一组 | 理解"参数 → 行为"的映射 |
| 任务 2 | 改 `otto_model.xml` 里腿的 `density`（600 → 1200），重跑 | 发现"机器人变重 → 同样的步态走不动了" |
| 任务 3 | 把地面 `friction` 从 0.9 改成 0.1，重跑 | 发现"地面太滑 → 迈不动脚" |
| 任务 4 | 把自己调出的最优参数填进任务卡 | 产出作品数据 |

**巡回话术**：
> "第 3 组问为什么改完反而走得远了？好问题 —— 你们把相位差改成了 0.75π，两条腿的节奏更接近同步，所以是'跳着走'，位移大但站不住。**记住这个反直觉的点**。"

**关键提醒（教师自查）**：任务 2、3 会让部分学生**走得更差**，这是刻意的。**不要急着帮他们调回来**，让他们发现"物理规律不可违背"。

**小结话术（必讲）**：
> "刚才我们用了 240 次试错，找到最优的**手写**步态。它能挪 31.8 厘米，但只站稳了 0.7 秒 —— 它是扑倒着往前挪。**写规则，撞到天花板了。**"

### 2.3 Tier B：强化学习（0:42 - 1:12 | 30分钟）

```
┌─────────────────────────────────────────────────────┐
│ 环节：不写规则，只定义目标，让机器自己学                            │
└─────────────────────────────────────────────────────┘
```

**教师演示（10分钟）**

1. 运行 `python 02_train_ppo.py`
2. 展示**基线**：随机策略平均回报 **-9.479** → "完全不会动的机器人，分数是负的，因为它马上摔倒"
3. 展示**训练曲线**：回报从 -9.5 爬到 200+
4. 指出耗时：**40 万步 = 1.9 分钟**

**话术（核心）**：
> "我们只写了一个东西 —— **奖励函数**。给前进速度加分，给摔倒扣分，给乱动扣分。剩下的算法是 PPO，它在电脑里试了几十万次。**1.9 分钟，够一节课。**"

**学生动手（16分钟）**

| 任务 | 操作 | 观察什么 |
|---|---|---|
| 任务 5 | 跑 `python 02_train_ppo.py`（40 万步） | 自己的学习曲线 |
| 任务 6 | 记录最终评估：回报 / 位移 / 最远 | 填入对比表 |
| 任务 7 | **改奖励函数**：把存活权重 0.6 降到 0.05，速度权重 1.5 提到 3.0，重跑 | 机器人会不会开始往前挪？ |

**任务 7 是本课的高潮**。预期结果（教师需预先验证）：

- 存活权重调低 → 机器人**不再在乎摔倒** → 可能开始有位移，但姿态崩坏
- 速度权重提高 → 位移增加，但可能学会"趴着往前蹭"这种作弊解

**话术（学生发现作弊解时用）**：
> "它学会的不是'走路'，是'蹭'。**这就是强化学习最容易被忽略的坑 —— 你给什么奖励，它就钻什么空子。** 在真实项目里，我们管这叫 reward hacking（奖励黑客）。"

### 2.4 收尾 + 落回实物（1:12 - 1:30 | 18分钟）

| 时间 | 时长 | 教师动作 | 学生动作 | 话术要点 |
|---|---|---|---|---|
| 1:12 | 5min | 全班对比：谁的最优步态位移最大？谁的 PPO 回报最高？ | 汇报 | "每个组的曲线都不一样，但**形状**是一样的 —— 这就是规律的威力" |
| 1:17 | 5min | 展示实物 OTTO 走两步 | 围观 | "现在这台真机器人，**走路的动作是人在 L1、L2 手工编排的**" |
| 1:22 | 4min | 抛出下节课问题 | 思考 | "如果让**实物** OTTO 也学走路，我们缺什么？（提示：仿真里的'摔坏了不心疼'，真机没有；而且真机每试错一次要 10 分钟）" |
| 1:26 | 4min | 填反馈表 + 收纳 | 填写 | "下节课我们讲 sim-to-real —— 怎么把电脑里学会的本事搬到真机上" |

**承接下节课的钩子**：
> "仿真里试错不要钱、还快 452 倍。真机上试错，一次十分钟，摔一次就可能烧一个舵机。**这就是为什么全世界都在用仿真。**"

## 四、常见问题应对

| 问题 | 原因 | 解决方法 |
|---|---|---|
| `ModuleNotFoundError: mujoco` | 环境没装或没激活 | 检查 `source .venv/bin/activate`；课前一周务必装好 |
| `FileNotFoundError: otto_model.xml` | 没 cd 到目录 | 强调"必须在 `L3-mujoco-rl/` 目录下运行" |
| 训练的图全黑 | 离屏渲染不支持 | **不是 bug**，本课用数据图；用 `03_analyze.py` 出图 |
| 训练特别慢 | 装了 CUDA 版 torch | 卸掉重装 CPU 版：`pip install torch --index-url https://download.pytorch.org/whl/cpu` |
| 回报一直是负的 | 步数太少 / 奖励权重没调 | 正常现象，任务 7 就是改这个 |
| 机器人一动不动 | 动作全在 ctrlrange 外 | 检查 `position` 执行器 ctrlrange |
| 终端刷出 `WARNING: Nan, Inf or huge value in QACC at DOF 9` | 机器人摔倒瞬间接触求解器数值发散 | **正常警告，不是错误**，训练照常继续；告诉学生"这是它摔得太狠了"，正好呼应仿真与真机的差别 |
