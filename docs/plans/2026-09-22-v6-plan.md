## 0. 为什么是 v6

Otto v4.1.1（2026-06-09 落地）入归档，6/11 ~ 9/21 共 **102 天**。归档期内云端 LLM 路线暴露出 4 个核心问题：

| 问题 | 表现 |
|---|---|
| 延迟 | 远场对话响应 >2s，学生体验断裂 |
| 隐私 | 答题记录 / 行为数据上云，晚托班敏感 |
| 工具 | Otto 现有硬件能力（舵机 / 灯环 / 扬声器）无法被 LLM 自然调用 |
| 成本 | 每次互动都走云端 API，规模化烧钱 |

v5.0.0 是归档版本，**v6 是重启版本**，定位切换：

> **v4.1.1**：硬件 BOM + 商业模式  
> **v6.0.0**：本地 AI 模型 + 实时决策 + 云端内容

## 1. 三层架构（已和飞熊对齐，2026-09-22 08:27）

```
┌────────────────────────────────────────────┐
│ Layer 3 · 内容层（云端 + 离线）            │
│   OpenMAIC   → 多智能体 AI 互动课堂        │
│   DeepTutor  → 学生个人学习追踪 + RAG      │
├────────────────────────────────────────────┤
│ Layer 2 · 工具层（端侧 · 本地）            │
│   Needle 14MB → 装饰函数 = 工具            │
│              → 调舵机 / 灯 / 扬 / 查知识    │
├────────────────────────────────────────────┤
│ Layer 1 · 决策层（端侧 · 实时）            │
│   Laya 32.8ms → Choice/Score/Noul 三原语   │
│              → 情绪 / 路由 / 安全护栏      │
└────────────────────────────────────────────┘
```

### 1.1 Layer 1 · Laya

| 维度 | 值 |
|---|---|
| 来源 | [NandhaKishorM/laya](https://github.com/NandhaKishorM/laya) |
| 协议 | Apache-2.0 |
| 参数量 | 421M（laya）/ 322M（laya-multilingual） |
| 单题延迟 | **32.8 ms**（T4 实测，比 Jev 快 8 倍）|
| 输入 | 文本 / 邮件 / JSON / 程序状态 |
| 输出三原语 | `choice`（选项） / `score`（序数评分） / `noul`（布尔概率 0-1） |
| Otto 用途 | 1) 情绪判断 2) 路由选择 3) 提示注入护栏 4) 内容分类 |

### 1.2 Layer 2 · Needle

| 维度 | 值 |
|---|---|
| 来源 | [cactus-compute/needle](https://github.com/cactus-compute/needle) |
| 架构 | Simple Attention Network（无 FFN，纯 attention） |
| 大小 | 14-29 MB / 运行时 28MB RAM |
| Otto 用途 | 1) 工具调用协议 2) 结构化抽取 3) 离线 LLM 后备 |

### 1.3 Layer 3 · OpenMAIC + DeepTutor

| 项目 | 来源 | Otto 用途 |
|---|---|---|
| **OpenMAIC** | [openmaic.io](https://openmaic.io) 清华 THU-MAIC | 1) 自动生成互动课堂 2) 多智能体扮演老师/同学 3) OpenClaw 集成（飞书触发） |
| **DeepTutor** | [hkuds/DeepTutor](https://github.com/hkuds/DeepTutor) 港大 HKUDS | 1) 学生个人知识库 2) 答题追踪 3) 错题分析 + 复习提醒 |

## 2. 30 天最小验证目标

> **只跑 1 个端到端 demo**，验证三层架构可行性。

### 2.1 推荐 demo 场景：DeepTutor 优先（采纳 canmou 2026-09-22 预案）

**理由**：
- 链路最短（Layer 1 + Layer 3 联动，不强行带 OpenMAIC）
- 数据闭环明确（学生答 → 记录 → 追踪 → 复习）
- 不依赖复杂硬件（舵机可不参与，只用麦克风/扬声器）

**场景脚本**：

```
学生问："勾股定理怎么证明？"
  ↓
Layer 1 (Laya):
  • 判紧急度 score: medium
  • 判学科 choice: math
  • 判困惑度 score: high
  ↓
Layer 2 (Needle):
  • 调工具 speak("让我想想怎么讲")
  • 调工具 retrieve(query="勾股定理证明")
  ↓
Layer 3 (DeepTutor):
  • 从学生个人知识库调出相关错题
  • 生成讲解 markdown
  • 同步记录：勾股定理 + 1 次 query
  ↓
Needle:
  • 调工具 speak(讲解文本)
  • 调工具 quiz(出一题相关题)
```

**验收标准**：

- [ ] Laya 决策延迟 < 100ms（含冷启动）
- [ ] Needle 工具调用成功率 > 95%
- [ ] DeepTutor 知识库命中 > 80%（口径：输入 query 在 1 次 retrieve 内命中 Top-3 相关文档 ≥ 80%）
- [ ] 全链路端到端延迟 < 5s
- [ ] 全程离线可跑（除 DeepTutor 同步）

### 2.2 时间盒

| 阶段 | 时间 | 产物 |
|---|---|---|
| **D1 算力评估（blocker）** | 1 天 | Raspberry Pi 5 / 端侧推理可行性报告 |
| D2-D4 环境搭建 | 3 天 | Needle + Laya + DeepTutor 装好 |
| D5-D7 链路串通 | 3 天 | 三层 IPC + 数据格式 |
| **D8-D10 Demo 1 硬承诺** | 3 天 | DeepTutor 优先场景过验收 |
| D11-D20 Demo 1 强化 | 10 天 | Demo 1 稳定性 + 边界 case |
| D21-D25 Demo 2（stretch） | 5 天 | OpenMAIC 课堂互动（仅 Demo 1 稳定后启动） |
| D26-D30 hardening | 5 天 | 文档 + 评估 + 修复 |

### 2.3 关键风险（canmou 9/22 已识别）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 三层集成时延 | demo 卡顿 | Laya + Needle 跑同一进程 |
| 离线一致性 | 学生数据丢失 | DeepTutor 本地优先，云端增量同步 |
| Needle 中文支持 | 中文指令识别差 | 必要时退回英文 prompt 或换模型 |
| Otto 算力 | Needle 14MB 跑不动 | 需 ESP32 / Raspberry Pi 性能评估 |
